01 / Research tracks

Connected questions. Distinct scopes.

GlobalFlowHub focuses on structured software systems. LITHARA explores how AI-assisted actions can be constrained, observed, and evaluated without confusing model output with operational truth.

03 / Illustrative research case

An AI says it changed a file. How would we know?

A model's confident report is not the same as permission to execute or evidence that the expected file state changed.

Candidate verification chain

  1. Identify the actor and exact proposed action.
  2. Check permissions, target, and current conditions.
  3. Observe the actual outcome of the trusted execution boundary.
  4. Independently inspect the relevant file state and evidence.
  5. Record the result, uncertainty, and any needed stopping condition.

What the evidence would mean

AI response: A claim that the action succeeded.

Tool response: Evidence about an invoked interface, not necessarily the intended real-world outcome.

Independent observation: A separate check of relevant actual state against predefined criteria.

Current classification: This is an illustrative test design, not a published executed experiment or passing result.

04 / Limits and interpretation

More capability does not automatically mean more authority.

Every stronger claim requires stronger evidence. A previous successful test does not create new operational permission.

Proposed is not implemented

An architecture diagram or AI-generated blueprint is not evidence of working code.

Tested is not universally verified

Test outcomes are limited by the tested environment, versions, assumptions, and observations.

Verified is not authorized

Independent evidence does not grant standing permission to run tools or change external systems.
